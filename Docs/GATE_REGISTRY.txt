WEBBING — GATE REGISTRY (v1)
=============================
Índice único de gates bloqueantes y de disciplina. Fuente operativa junto con
SKILL.md §6. Si un módulo y este registro difieren, reportar antes de operar.

Leyenda DESTINO: módulo o acción si el gate falla.

--------------------------------------------------------------------------------
PROYECTO — GATES GLOBALES (SKILL.md §6)
--------------------------------------------------------------------------------

GATE 1 — Estrategia cerrada
  CUÁNDO:  Después de M3, antes de M4.
  PASA SI: Posicionamiento, marca y tipografía definidos y aprobados por humano.
  FALLA →: No generar conceptos. Volver a M0-M3 según vacío.

GATE 2 — Veto del CDL
  CUÁNDO:  Después de M5.5.
  PASA SI: Dirección pasa CDL + IA Spec (CDL-1) derivada del arquetipo, no default
           + Experience Spec (CDL-1) completa (≥1 flujo crítico, pasos, mobile-first,
           estados según gobernanza Ligera/Media/Completa).
  FALLA →: M4-M5.5 con feedback CDL. IA Spec genérica → rehacer CDL-1 IA Spec.
           Flujos/estados faltantes → rehacer CDL-1 Experience Spec. Máx 2 iter → humano.

GATE 3 — Pre-producción
  CUÁNDO:  Después de M9.8 y M8.6.
  PASA SI: Build completo; M9.8 signature; IA Spec respetada; flujos críticos de
           Experience Spec implementados (estados documentados, mobile usable);
           M8.6 PASA o PASA CON AJUSTES (ninguna dimensión PERDIDO; Generic Drift no
           CRÍTICO — incluye 3+ tells ANTI-AI-SLOP); B0-B5 si hay backend.
  FALLA →: Listar deuda. M8.6 FALLA → destino por dimensión (M4/M4.5/M5/M5.5/build).
           Flujo crítico roto → M8/M8.2.

GATE 4 — Deploy
  CUÁNDO:  Dentro de M10, antes de publicar.
  PASA SI: Aprobación explícita del humano. B4 launch + B6 recovery si backend.
  FALLA →: No deploy autónomo.
