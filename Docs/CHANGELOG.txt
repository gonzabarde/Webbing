2026-07-06 — STACK: NEXT.JS/ASTRO COMO PISO REAL (no vanilla) + REACT BITS CON SESGO POR ELEMENTO
-------------------------------------------------------------------------------------------------
Módulos afectados: M8.1 (Technical Architecture Engine, v2->v2.1), M9.3 (Motion
Pattern Library, v2.3->v2.4). Estado: ACTIVA. Permanente.

Cambio 1 (M8.1): la tabla de perfiles de stack NUNCA listó "vanilla HTML/CSS/JS"
como opción — incluso "Marketing site estático" ya decaía "Astro o Next.js (static
export)". La sección QUÉ NO USAR tenía la regla ("stack sin framework: solo con
razón técnica específica") pero no se hacía cumplir. Se refuerza explícitamente:
vanilla no es un perfil válido por default en ningún caso, ni siquiera el sitio más
simple — exige la misma barra de justificación que cualquier otro desvío.

Cambio 2 (M9.3): se agrega un default explícito según si el elemento es la firma o
no. Firma: default NO acelerar con librería (como ya estaba). No-firma (hover de
cards, reveals secundarios): default INVERTIDO — sesgar A FAVOR de acelerar con
librería (React Bits u equivalente) salvo objeción concreta; el test anti-clonación
de M12 sigue corriendo siempre, cambia dónde arranca la moneda, no si se aplica.

Razón: el operador pidió que Webbing priorice Next.js + React Bits en vez de
vanilla. Se verificó contra la evidencia real de la sesión: B0 nunca eligió vanilla
por mal criterio — Runa y el Ecos original quedaron en vanilla porque el operador
bloqueó auth/pagos reales en esas corridas (sin esa funcionalidad, un framework
completo hubiera sido teatro); apenas se destrabó (Ecos vía Cursor), el sistema fue
directo a Next.js con Server Actions reales. O sea: el criterio ya funcionaba: lo
que faltaba era que M8.1 hiciera CUMPLIR su propio piso (Astro/Next, no vanilla) en
vez de permitir el desvío sin barra de justificación — mismo patrón que el agujero
de M8.6 no cableado a GATE 3. Sobre React Bits: no se fuerza "siempre" porque hay
un caso real donde SÍ falló el test anti-clonación (la firma de Ecos, efecto de
onda genérico) — forzarlo ahí reabriría el mismo riesgo de sameness que el
Principio 10 existe para evitar. El sesgo por defecto en NO-firma preserva la
única protección verificada (el test) mientras acelera donde no hay riesgo real.

Qué NO cambia: B0 sigue defaulteando a Supabase/Prisma igual que antes (precedente
ya existía para "default operativo, override con justificación" — este cambio
aplica la misma lógica al frontend). El test anti-clonación de M12 no se toca.
